# Contact form: Zoho Mail

The contact form posts to `/api/contact`, which sends project briefs and optional
attachments through Zoho SMTP. Messages are sent from and delivered to
`hello@mzfortech.com`. The visitor's email is set as Reply-To, so replying to a
brief reaches the visitor without impersonating their address as the sender.

The form requires the client's full name, email, international phone number
(selected using a country / calling-code dropdown), and project description. Company / organization
is optional. Phone numbers are normalized to `+` followed by 7–15 digits; this
checks format, not ownership or whether a number is reachable.

The dropdown includes the supported countries and territories, with Egypt selected
by default. Visitors enter their national number separately; standard national
prefixes (such as Egypt's leading zero) are normalized before submission. A
successful submission replaces the form with a confirmation card containing the
inquiry reference and next steps, with an option to start another brief.

Notifications include a branded HTML layout and a plain-text alternative, client
details, project overview, attachment filename, an inquiry reference, and the
submission time in Cairo. Reply and call links provide direct follow-up. Arabic
and other right-to-left descriptions use automatic text direction. Notifications
are only sent to the configured inbox; no automatic client email is sent.

## Activate delivery

1. Set `ZOHO_SMTP_PASSWORD` in the ignored `.env.local` file to the mailbox's
   SMTP password. With two-factor authentication enabled, generate a Zoho
   application-specific password. Never commit passwords or share them in chat.
2. The supplied account configuration uses `smtp.zoho.com`, port `465` (SSL).
   Confirm the host in Zoho Mail's Server Configuration Details for this mailbox.
   Paid organization accounts may require `smtppro.zoho.com`; other data centers
   may use different hosts. Port `587` is also supported with mandatory STARTTLS.
3. In your hosting provider, add all six variables from `.env.example` as
   server-side environment variables, including the real password. Do not prefix
   them with `NEXT_PUBLIC_`. Local configuration does not configure production.
4. Restart the local server or redeploy production after setting the variables.
5. Submit a short brief through `/contact`. Confirm it arrives in the mailbox
   and that Reply addresses the visitor. Also check an attachment if needed.

Until the password is configured, the endpoint returns a setup message (503),
not a successful delivery confirmation. SMTP delivery failures return 502.

## Delivery diagnostics and safeguards

Successful SMTP submissions return an inquiry reference, shown beneath the form.
Search Vercel runtime logs for that reference: `Contact inquiry accepted by SMTP`
means Zoho accepted the message, not that it has reached the inbox. The log also
includes the SMTP message ID and accepted/rejected recipients so you can verify
the production destination. Check Spam,
Quarantine, inbox rules, and Zoho mail logs if it is missing. Failed SMTP attempts
log the reference and an error code without logging the client's brief or password.

Server-side checks enforce field types, lengths, international phone format,
email format, allowed project choices, and the attachment size limit. Duplicate
single-value fields are rejected. User-provided HTML is escaped in the email,
and the recipient is fixed by server configuration. Requests with a mismatched
Origin are rejected. A triggered honeypot returns an error rather than claiming
delivery succeeded, but Origin checks and the honeypot are not full spam protection.
Enable durable rate limiting in the Vercel firewall or a shared backing store;
the application does not currently provide it. Attachments are untrusted and are
not malware-scanned by this application: do not open unexpected files without
scanning them. Vercel may reject large request bodies before this route runs.

## Domain DNS

These records are managed at your DNS provider, not in this repository. Confirm
the account-specific records in the Zoho admin console before making changes.

| Type | Host | Priority | Value |
| --- | --- | --- | --- |
| MX | @ | 10 | mx.zoho.com |
| MX | @ | 20 | mx2.zoho.com |
| MX | @ | 50 | mx3.zoho.com |
| TXT | @ | — | v=spf1 include:zohomail.com ~all |

Maintain only one SPF record: if other services already send email for this
domain, merge the Zoho include into the existing SPF policy rather than adding
a second SPF record. Configure DKIM using the selector and key generated by
Zoho, then verify it in the admin console. IMAP and POP settings are not needed
by the contact form.

Reference: https://www.zoho.com/mail/help/zoho-smtp.html
